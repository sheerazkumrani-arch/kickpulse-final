# ⚽ Pitchside Notes (KickPulse Final)

**Football previews and sharp analysis, served fast.**

Pitchside Notes is a lightweight static football preview and analysis site, the companion blog of the **KickPulse** live scores site. It is built with **Node.js**, powered by a single build script, and deployed on **Vercel**. There is no heavy framework and no database. You write an article in Markdown, push it to GitHub, and the site rebuilds itself within moments.

---

## ✨ Why This Project Works

- **Simple to write:** every article is just a Markdown file.
- **Fast to load:** the finished site is plain static HTML, CSS and images.
- **Newest first, automatically:** your latest article becomes the first slide, the first card on the home page and the first item in the article lists.
- **Never a blank picture:** if an article has no image, the build draws a branded cover for it.
- **Safe to publish:** the build script checks your images and metadata and lists any problems before you go live.
- **Visitor insights:** the Vercel Web Analytics script is added to every page automatically.
- **Hands-free deployment:** push to GitHub and Vercel rebuilds the site.

---

## 🗂️ Project Structure

| File / Folder | What It Does |
|---|---|
| `build.js` | The heart of the project. It reads every article in `content/*.md`, copies the `static/` folder, checks images and metadata, builds the pages, adds Vercel Web Analytics to every page, creates the sitemap and `articles.json`, and writes the finished site to `dist/`. |
| `vercel.json` | Tells Vercel to run `node build.js`, serve the `dist/` folder, and redirect the old Orlando article addresses to the current article. |
| `content/*.md` | Your articles. Any file whose name starts with `_`, or whose top block contains `draft: true`, is skipped. |
| `static/` | Everything that is not an article: `style.css`, `slider.css`, `favicon.svg`, `og-default.jpg` (the default sharing picture) and article images inside `static/images/`. |
| `slider.txt` | Optional. Controls which slides follow the newest article on the home page slider. |
| `verify.txt` | Optional. Holds your Google Search Console verification code. |
| `dist/` | Generated by the build. Never edit it by hand. |

All of these sit in the **root** of the repository, next to the `content/` and `static/` folders, not inside any folder.

## 🚀 Getting Started

### What You Need

- **Node.js 18 or newer.** Check with `node -v`. Download it from [nodejs.org](https://nodejs.org).
- A **GitHub** account, where your code lives.
- A **Vercel** account, where your live site is built and hosted.

### Run the Site on Your Computer

1. Download the project from GitHub (**Code → Download ZIP**) and unzip it.
2. Open a terminal inside the project folder.
3. Build the site:
   ```bash
   node build.js
   ```
4. Open `dist/index.html` in your browser to preview the result.

### Where Everything Lives

| Place | Role |
|---|---|
| **GitHub repository** | The master copy of all your files. Always trust this one. |
| **Vercel** | Reads the GitHub repository and builds the live site. It is never your only copy. |
| **Your computer** | A backup folder. Refresh it after every successful update. |

## 📝 Adding a New Article

Publishing a match preview takes about five minutes.

### 1. Prepare your image (recommended)

Save your image inside `static/images/` with a **lowercase letters, numbers and hyphens** name, for example `derby-preview.jpg`. Use a **1600×900** image, in `.jpg` format, **under 250 KB**.

Two shortcuts save time:

- An image named exactly like the article file (`derby-preview.jpg` for `derby-preview.md`) is picked up automatically as the top picture.
- Images named `derby-preview-2.jpg`, `-3.jpg` and `-4.jpg` are placed inside the article automatically.

No image at all? The build draws a branded cover card for you.

### 2. Create the article file

Add a `.md` file inside `content/`. Use **lowercase letters, numbers and hyphens only**, for example `derby-preview.md`. The file name becomes the web address, so choose it carefully and do not rename it later.

### 3. Add the top block

Place this at the very top of the file:

```markdown
---
title: Your Article Title
description: A clear summary of 120 to 155 characters that tells readers and search engines what the article is about.
date: 2026-11-18
category: Match Preview
image: /images/derby-preview.jpg
imageAlt: A short description of what the image shows
---
```

| Field | Needed? | Notes |
|---|---|---|
| `title` | Required | The headline. |
| `description` | Required | Aim for **120–155 characters**. Google shows it under your title. |
| `date` | Required | Format `YYYY-MM-DD`. **The newest date goes first everywhere**, so give a new article today's date. |
| `category` | Recommended | Creates the topic pages. Defaults to "Articles". |
| `image` | Recommended | Starts with `/images/`. |
| `imageAlt` | Needed with an image | Describes the picture for accessibility and SEO. |
| `author` | Optional | Defaults to "Pitchside Notes". |
| `draft` | Optional | `draft: true` keeps the article unpublished. |

Write your article below the top block. Use `##` for headings. Aim for **500 words or more**, because the build warns about very short articles.

### 4. Test it locally

```bash
node build.js
```

Read the list at the end. The site still builds when something is wrong, but the list tells you exactly what to fix. Aim for **"No problems found."**

### 5. Publish

Commit and push to GitHub. **Vercel rebuilds the site automatically**, and your article goes live.

## 🏆 Newest Article Comes First

The article with the newest `date:` is placed first automatically in:

- the **home page slider** (always the first slide),
- the **Latest articles** list on the home page (the home page shows all articles),
- the **All articles** and category pages,
- the **Latest articles** box in the sidebar.

---

## 🎞️ Controlling the Slider

After the newest article, the slides follow the lines in `slider.txt`. One line is one slide:

```text
article:orlando-city-vs-fc-cincinnati-prediction-preview-team-news-lineups
article:another-article-file-name
```

Use the article file name **without** `.md`. If `slider.txt` is missing or empty, the 5 newest articles are shown. Add `latest:6` on its own line to include the 6 newest articles that are not already there. You can also add your own banner:

```text
/images/banner.jpg | Title | Short text | /articles/some-article/ | Button text
```

---

## 🔎 Google Search Console

Put **only** the `content` value of the Search Console HTML tag into `verify.txt` (for example `abc123XYZ`, nothing else). The build adds the verification tag to every page.

---

## 📊 Vercel Web Analytics

`build.js` adds the official Vercel Web Analytics script to **every page** during the build, so you never add it by hand. One setting must be switched on in Vercel for it to count visits:

1. Open your project in the Vercel dashboard.
2. Click the **Analytics** tab.
3. Click **Enable**, then redeploy once.

After the next deployment, open your live site and look for a request to `/_vercel/insights/view` in your browser's Network tab. Numbers appear in the **Analytics** tab shortly after.

## 🚧 Working on Drafts

Not ready to publish? Start the file name with an underscore (`_next-weekend-ideas.md`) or add `draft: true` to the top block. The build skips it until you are ready.

---

## 🔍 Quick Checklist Before You Push

- [ ] Image is a `.jpg` in `static/images/`, under 250 KB, sized 1600×900
- [ ] File names use only lowercase letters, numbers and hyphens
- [ ] `title`, `description` and `date` are present, and the date is today for a new article
- [ ] Description is between 120 and 155 characters
- [ ] `node build.js` ends with **"No problems found."**

---

## 🛡️ Staying Safe When Updating

- **Back up first:** download a ZIP from GitHub before changing `build.js` or `vercel.json`.
- **Know your project:** this repository (`kickpulse-final`) is separate from the KickPulse scores site. Never copy `build.js` or `vercel.json` between projects.
- **Change one thing at a time,** then check the Vercel deployment shows **Ready** before the next change.
- **If something breaks:** open the project's **Deployments** tab in Vercel and promote the last working deployment to production, then fix the problem calmly.

---

## 🚀 Deployment at a Glance

1. You write an article and push it to GitHub.
2. Vercel reads `vercel.json` and runs `node build.js`.
3. The script checks your content, builds every page (with Web Analytics included), and creates `dist/`.
4. Vercel publishes the contents of `dist/`.

Write, check, push, and let Vercel do the rest.
